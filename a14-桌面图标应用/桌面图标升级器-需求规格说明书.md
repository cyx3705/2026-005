# 桌面图标升级器需求规格说明书

文档版本：V1.0  
日期：2026-07-19  
目标目录：`C:\OneHistory\OneHistory-Projects\2026-005-小型作业集合\a14-桌面图标应用`  
计划技术栈：C# / .NET 8 / WPF / Windows 10 与 Windows 11  
当前阶段：仅需求定义，不进行编码

## 1. 产品目标

开发一款 Windows 桌面图标智能升级工具，能够快速、完整地发现桌面上可独立修改图标的项目，自动提取原始图标、判断背景类型、生成高质量多尺寸 ICO，并一键替换桌面图标。

系统必须在任何替换发生前保存可验证的原始状态，并提供一键还原全部图标和单项还原能力。用户不需要预先制作 ICO，也不需要理解快捷方式、注册表、图标索引或 Windows 图标缓存。

## 2. 当前问题

现有工具存在以下核心问题：

1. 扫描和处理速度慢，处理期间界面容易卡顿。
2. 桌面项目发现不完整，只处理部分 `.lnk`，遗漏公共桌面、URL、文件夹和系统桌面图标。
3. 经常只提取 32px 小图后放大，导致生成图标模糊。
4. ICO 内尺寸不完整，Windows 在不同缩放比例下使用低质量帧。
5. 背景类型判断粗糙，透明图标、已有有色背景图标被错误处理。
6. 图标边缘存在锯齿、黑边、白边或颜色脏污。
7. 替换后缺少可靠备份，无法恢复到修改前状态。
8. 新增桌面项目不能被自动识别和升级。
9. 操作结束后缺少逐项验证，失败项目可能被静默忽略。

## 3. 用户与核心场景

目标用户为希望统一 Windows 桌面图标风格的普通 Windows 用户，不要求具备管理员、图像处理或注册表知识。

核心场景：

1. 用户启动软件，程序快速列出当前桌面与公共桌面的全部可管理项目。
2. 用户点击“一键升级全部”，系统自动提取、处理、生成 ICO、备份原状态、替换并验证。
3. 用户选择部分项目，仅升级选中的图标。
4. 桌面出现新快捷方式后，用户刷新或再次一键升级，只处理新增或未升级项目。
5. 用户不满意升级结果，点击“一键还原全部”，恢复到首次升级前的图标。
6. 用户只想还原某一项，可对单项执行还原。
7. 某些项目无法处理时，其他项目继续完成，并在结果页明确列出失败原因。

## 4. 范围定义

### 4.1 V1 必须支持

| 桌面项目类型 | 发现 | 升级 | 还原 | 说明 |
| --- | --- | --- | --- | --- |
| 当前用户桌面 `.lnk` | 是 | 是 | 是 | 保留目标、参数、工作目录等非图标属性 |
| 公共桌面 `.lnk` | 是 | 是 | 是 | 写入需要权限时再请求提升权限 |
| `.url` 互联网快捷方式 | 是 | 是 | 是 | 备份并更新 IconFile、IconIndex |
| 目标为 EXE/DLL 的快捷方式 | 是 | 是 | 是 | 优先读取 PE 内全部图标资源 |
| UWP / Microsoft Store 应用快捷方式 | 是 | 是 | 是 | 优先从应用清单和高分辨率资产提取 |
| 桌面文件夹 | 是 | 是 | 是 | 使用 `desktop.ini` 管理并完整备份属性与原文件 |
| “此电脑、回收站、网络、控制面板、用户文件”等系统图标 | 是 | 是 | 是 | 备份对应 HKCU 图标配置；回收站需分别处理空/满状态 |
| 新增桌面项目 | 是 | 是 | 是 | 刷新或下一次一键升级时自动发现 |

### 4.2 明确边界

- 普通文件的图标通常由文件扩展名关联统一控制，Windows 不支持安全的单文件图标替换。V1 必须显示为“不可独立替换”，不得为修改一个文件而改变整个扩展名的系统关联。
- V1 不修改 EXE/DLL 本体中的资源，不进行可执行文件注入或签名破坏。
- V1 不删除、移动或重命名用户桌面文件。
- V1 不从网络自动搜索或下载第三方图标。
- 无法安全修改的项目必须出现在扫描结果和完成报告中，不得静默遗漏。

## 5. 图标来源提取需求

系统应按以下优先级获取每个项目的最佳原始图标：

1. 快捷方式已明确指定的 ICO、PNG、EXE、DLL 和图标索引。
2. EXE/DLL 的 RT_GROUP_ICON 与 RT_ICON 资源，保留资源组中的所有尺寸。
3. UWP 应用清单中的高分辨率 Logo 资产。
4. 目标文件的 Windows Shell 高分辨率图标。
5. Windows 系统资源中的文件夹或通用文件图标。

质量规则：

- 必须优先选择可用的最大尺寸，优先顺序为矢量资源、1024、512、256、128、64、48、32。
- 禁止在存在 128px 或更大资源时使用 32px 系统小图。
- 原始最大尺寸低于 64px 时应标记为“低分辨率来源”，但仍允许处理。
- 资源组包含多个不同图标时，应遵守快捷方式 IconIndex；索引无法解析时才使用默认资源组。
- 提取失败必须记录具体来源、图标索引和失败原因。

## 6. 背景类型判定

每个原图标必须自动分类为“透明背景”“有色背景”或“低置信度”。

### 6.1 透明背景判定

满足以下任一主要条件时判为透明背景：

- 图像四角存在明显透明像素，且透明像素占画布比例不低于设定阈值。
- 外围边缘形成连续透明区域，主体与画布边缘没有不透明背景连接。
- ICO/PNG 的 alpha 通道明确包含透明背景。

抗锯齿产生的半透明边缘不得被误判为有色底。统计主色时必须忽略全透明像素，并降低纯白、纯黑和低饱和中性色的权重。

### 6.2 有色背景判定

同时满足以下特征时判为有色背景：

- 四角及外边缘大部分为不透明像素。
- 边缘背景颜色在允许色差范围内保持连续或属于同一渐变。
- 主体外存在稳定、可作为图标底板的颜色区域。

有色背景可以是纯色、轻微渐变或已有方形底板，不要求严格单色。

### 6.3 低置信度处理

- 自动处理仍应选择风险最低的结果，不阻断“一键升级全部”。
- 项目列表中标记低置信度状态。
- 用户可在单项详情中手动切换“透明底处理”或“有色底处理”并重新生成。
- 手动选择只影响该项目，并保存在本地规则中供下次复用。

## 7. 图标重绘规则

### 7.1 有色背景图标

- 保留原有背景颜色或原有背景渐变，不额外添加其他颜色底板。
- 按视觉主体居中裁切到正方形，背景需要覆盖整个正方形画布。
- 将正方形改为圆角矩形，默认圆角半径为边长的 22%，可在设置中调整。
- 圆角外像素 alpha 必须为 0。
- 不得出现缩小方图套在透明外框中的“双层方块”效果。

### 7.2 透明背景图标

- 从非透明主体像素中提取主要颜色 P。
- 新背景颜色 B 按 `B = P × (1 - R) + 白色 × R` 计算，默认向白偏移比例 R 为 38%，设置范围为 25% 至 55%。
- 新背景为圆角矩形，可使用非常轻微的同色系明暗变化，但不得改变主色相或加入无关颜色。
- 原主体保持透明边缘，居中放置，默认占画布的 72% 至 78%。
- 白色或黑色单色主体无法得到有效主色时，使用可读性良好的系统蓝作为背景基色，并保证主体对比度。

### 7.3 通用图像质量

- 使用至少 1024×1024 的内部工作画布。
- 所有缩放在预乘 alpha 或等效正确色彩处理下完成，防止黑边和白边。
- 每个目标尺寸从高分辨率母版独立缩小，不允许逐级缩小。
- 使用高质量重采样算法，不允许最近邻或系统默认低质量拉伸。
- 只允许轻量锐化；禁止对低分辨率来源过度锐化制造噪点和光晕。
- 颜色处理使用 sRGB，并保留 alpha 通道。

## 8. ICO 生成要求

每个升级图标必须自动生成独立 ICO，至少包含以下尺寸：

`16、20、24、32、40、48、64、96、128、256px`

要求：

- 256px 帧使用 PNG 压缩写入 ICO。
- 16 至 48px 必须逐尺寸检查边缘、主体占比和可识别性。
- ICO 写入后必须重新读取目录，验证每个要求尺寸真实存在。
- 生成文件采用稳定路径，快捷方式不能引用临时目录。
- 文件名需要避免冲突；内部使用项目稳定 ID，显示名称可以保留中文。
- 生成图标存储在 `%LocalAppData%\OneHistory\DesktopIconUpgrader\Icons`。
- 清理缓存时不得删除仍被快捷方式或备份引用的 ICO。

## 9. 一键升级流程

点击“一键升级全部”后按以下事务顺序执行：

1. 扫描当前用户桌面、公共桌面和系统桌面图标。
2. 建立本次操作清单并识别新增、已升级、已跳过和不可处理项目。
3. 对所有即将修改的项目检查原始基线备份；没有备份时先完成备份。
4. 并行提取原始图标和生成母版，限制并发数量，避免耗尽 CPU 与磁盘。
5. 生成并验证多尺寸 ICO。
6. 逐项原子写入新图标引用；单项失败不得破坏其原设置。
7. 发送 Windows Shell 图标变更通知并刷新图标缓存，不默认重启 Explorer。
8. 重新读取每一项的当前图标引用，验证是否写入成功。
9. 展示完成报告：成功、失败、跳过、低质量来源、低置信度和不可处理项目。

“一键升级全部”必须满足：

- 已升级且源图标与规则未变化的项目直接跳过，不重复生成。
- 新增项目自动进入处理队列。
- 用户可以随时取消；取消后已完成项目保持有效，未开始项目不发生修改。
- 界面全程保持响应，并实时显示总体进度和当前项目。

## 10. 备份与一键还原

### 10.1 基线备份

系统首次修改某个项目之前必须建立不可覆盖的原始基线。后续再次升级不得用升级后的状态覆盖原始基线。

每个项目至少备份：

- 稳定项目 ID、项目类型、原路径、目标路径和采集时间。
- `.lnk` 的原 IconLocation、IconIndex、目标、参数、工作目录和说明。
- `.url` 的原始文件副本及 IconFile、IconIndex。
- 文件夹 `desktop.ini` 原文件、文件夹属性和 desktop.ini 属性。
- 系统图标对应注册表键值；回收站包含空、满两个状态。
- 原始图标资源的本地副本，防止原 EXE、DLL 或 ICO 被移动、升级或删除。
- 原始数据和备份文件的 SHA-256，用于还原前完整性检查。

备份存储在 `%LocalAppData%\OneHistory\DesktopIconUpgrader\Backups`，按设备和操作批次组织。备份元数据应使用可迁移的 JSON 清单或等价开放格式。

### 10.2 一键还原全部

点击“一键还原全部”后：

1. 校验备份清单和备份文件完整性。
2. 预览将还原的项目数量、缺失项目和可能的路径冲突。
3. 将所有受管项目恢复到首次升级前的基线图标状态。
4. 对已删除的桌面项目只报告，不擅自重新创建；用户明确选择后才可恢复项目本身。
5. 对已移动项目使用稳定 ID、目标路径和文件标识尝试重新匹配。
6. 刷新 Windows Shell 图标状态并逐项验证。
7. 输出成功、失败和无需还原的明细。

### 10.3 单项还原与还原保护

- 每个已升级项目提供“还原此项”。
- 还原动作本身生成操作日志，但不得改变原始基线。
- 还原失败不得清除备份。
- 用户主动删除备份前必须明确确认，并说明删除后将无法还原。

## 11. 性能要求

以下指标以普通 SSD、4 核 CPU、200 个桌面项目为验收基准：

| 指标 | 目标 |
| --- | --- |
| 冷启动至可操作界面 | 不超过 1.5 秒 |
| 首次完整扫描 | 不超过 3 秒 |
| 缓存命中后的增量扫描 | 不超过 0.7 秒 |
| 100 个正常图标的一键升级 | 不超过 20 秒 |
| 100 个项目的一键还原 | 不超过 6 秒 |
| 取消操作响应 | 不超过 1 秒 |
| 正常工作内存 | 不超过 300 MB |

实现必须采用异步扫描、受控并行处理、图标资源哈希缓存和增量更新。不得为每一个快捷方式单独启动 PowerShell 进程，不得在 UI 线程执行图像处理或磁盘密集操作。

## 12. 界面需求

主界面第一屏直接展示可操作工具，不设置营销页。

主要区域：

- 顶部工具栏：一键升级全部、一键还原全部、刷新、取消、设置。
- 项目列表：原图预览、新图预览、名称、类型、来源质量、背景判定、当前状态。
- 筛选：全部、未升级、已升级、可还原、失败、低置信度、不可处理。
- 单项操作：升级、重新生成、切换处理模式、还原、查看错误。
- 底部状态栏：已扫描数量、成功数量、失败数量、总体进度。

操作要求：

- 危险操作必须显示影响范围，但确认步骤不得冗长。
- 一键还原全部使用醒目且与升级按钮区分的样式。
- 长名称和长路径不得撑破布局，支持省略显示和完整工具提示。
- 处理过程中列表尺寸不得因状态文本变化而跳动。
- 必须支持 Windows 100%、125%、150%、175% 和 200% 显示缩放。

## 13. 权限与安全

- 默认以普通用户权限运行。
- 修改当前用户桌面和 HKCU 配置不请求管理员权限。
- 修改公共桌面或确实受保护的位置时，仅对该操作请求权限提升，不要求软件始终以管理员身份运行。
- 权限提升取消后，其余无需提升的项目继续处理。
- 不执行来源不明的脚本，不修改可执行文件资源，不上传用户路径、图标或备份数据。
- 日志中隐藏可能包含敏感信息的用户参数，除非用户主动导出诊断包。

## 14. 数据与日志

系统需要维护以下本地数据：

- 项目索引：稳定 ID、路径、类型、最近扫描时间、当前状态。
- 原始基线：首次修改前的不可覆盖备份。
- 操作批次：升级或还原时间、输入规则、成功与失败明细。
- 图标缓存：源哈希、处理规则版本、生成 ICO 路径、引用计数。
- 用户规则：单项强制透明底/有色底、圆角和向白偏移覆盖值。

日志等级至少包括信息、警告和错误。用户界面展示可理解的中文错误，详细日志保留异常类型、Windows 错误码和处理阶段。

## 15. 错误处理

以下情况必须有明确处理策略：

- 快捷方式目标不存在：优先使用快捷方式现有 IconLocation；仍失败则标记失败。
- 图标源损坏：不替换，保留原状态并记录错误。
- 写入被拒绝：按需请求提升；仍失败则跳过。
- ICO 生成后校验失败：删除无效输出，不写入快捷方式。
- 替换成功但验证失败：立即回滚该单项，并报告回滚结果。
- 图标缓存未及时更新：先发送 Shell 通知，再提供“强制刷新缓存”；不得默认强制结束 Explorer。
- OneDrive 桌面暂不可用：等待可取消，并提示同步状态。
- 备份缺失或校验失败：禁止覆盖当前图标，提示用户选择其他备份或保留现状。

## 16. 技术约束

- 使用 C#、.NET 8 和 WPF，发布为 Windows x64 自包含应用。
- 使用 Windows Known Folder API 查找桌面路径，不硬编码 `C:\Users\用户名\Desktop`。
- 使用 Shell Link COM 接口或原生 Shell API 批量读取快捷方式，不通过逐项 PowerShell 子进程处理。
- 使用 Windows 资源 API 读取 PE 图标组和 UWP 资产。
- 图像处理使用支持正确 alpha 和高质量重采样的成熟库；ICO 容器写入后必须自行验证目录。
- 采用 MVVM 或等价分层，扫描、提取、渲染、替换、备份、还原和 UI 不得耦合在单一类中。
- 所有修改操作必须支持取消令牌、进度报告和结构化结果。

建议模块边界：

| 模块 | 职责 |
| --- | --- |
| DesktopInventory | 枚举用户桌面、公共桌面、系统图标及新增项目 |
| IconSourceResolver | 按优先级提取最佳原始图标 |
| BackgroundClassifier | 透明底、有色底和置信度判定 |
| IconRenderer | 生成高质量母版与各尺寸帧 |
| IcoWriter | 写入并验证多尺寸 ICO |
| DesktopIconApplier | 按项目类型应用新图标并验证 |
| BackupStore | 保存不可覆盖基线、校验和操作批次 |
| RestoreService | 单项及一键还原、冲突检测和验证 |
| ShellRefreshService | 通知 Explorer 刷新图标状态 |

## 17. 验收标准

### 17.1 功能验收

1. 含 50 个 `.lnk`、10 个 `.url`、10 个文件夹、5 个系统图标和 10 个普通文件的测试桌面，所有项目必须被列出并正确分类。
2. 一键升级后，全部可支持项目均指向有效的新 ICO；不可处理项目必须有明确原因。
3. 新 ICO 重新读取后包含规定的全部尺寸。
4. 透明底测试集全部生成“主色向白偏移”背景，不出现纯白不可见主体。
5. 有色底测试集保留原背景颜色并直接形成圆角，不出现二次底板。
6. 256px、125% 和 200% 缩放下无明显锯齿、黑边、白边和模糊放大痕迹。
7. 升级完成后新增 5 个快捷方式，再次升级只处理新增项目和发生变化的项目。
8. 一键还原后，所有可恢复项目的图标引用和视觉结果与首次升级前一致。
9. 连续升级三次后再还原，仍恢复首次升级前基线，而不是恢复到上一次升级结果。
10. 替换过程中模拟单项写入失败，该项保持原图标，其他项目继续完成。

### 17.2 性能验收

性能测试必须达到第 11 节指标，UI 在扫描、生成、升级和还原过程中保持可拖动、可取消，不出现“未响应”。

### 17.3 还原可靠性验收

对 `.lnk`、`.url`、文件夹、公共桌面项和系统图标分别完成“升级 → 关闭程序 → 重启电脑 → 一键还原”测试。还原必须不依赖内存状态，备份文件损坏时必须阻止不安全还原。
