# MC 2.5D 地形生成模型 —— 实现说明

按 [PLAN.md](PLAN.md) 实现。本文件记录**实际怎么跑的**、以及**哪里偏离了原计划、为什么**。

## 快速开始

```powershell
cd C:\Users\Administrator\Desktop\测试
.\venv\Scripts\activate

python gen_worlds.py --worlds 12 --radius 32   # §1.1 生成真实存档（~15 分钟）
python extract.py                              # §1.2 .mca → dataset.npz
```

## 相对 PLAN 的偏离

### 1. 数据源：走 A 路线，但这台机器上本来没有 MC

PLAN 的 B 路线（用现有存档）不可行——全盘扫过没有任何 `.mca`，也没装 MC。
所以下了 Temurin JDK 21 + Paper 1.21.8，用 `gen_worlds.py` 按 12 个 seed 现生成。
每个世界 forceload 64×64 = 4096 个区块（1024×1024 方块 = 4 个满 region）。

`generate-structures=false`——村庄/神殿这类人工建筑会污染地形分布。

> 判停条件踩过一次坑：一开始按「region 文件大小不再增长」判定生成结束，
> 结果区块 30 秒就生成完了，`save-all` 还在持续微调几十 KB，条件永远不成立，
> 每个世界白等 30 分钟。改成**直接读 region 头部扇区表数目标方阵内的区块数**，
> 确定性判停，每个世界 ~60 秒。

### 2. `.mca` 解析：自研，不用 anvil-parser 也不用 amulet-core

PLAN §1.2 的风险提示是对的（anvil-parser 对 1.18+ 支持不全），但 amulet-core 在
Python 3.12 上装起来同样痛苦。region + NBT 格式本身很简单，`mcio.py` 用 numpy +
标准库全部自己解（~200 行），顺带能跳过 `entities`/`structures` 这些用不到的大子树，
解析速度约 **2 秒/region**。

两个把游标写飞的坑（都已修复，注释留在代码里）：

- `self.pos += self._u2()` —— Python 先读旧的 `self.pos` 再算右边有副作用的表达式，
  `_u2` 自己推进的 2 字节被吞掉。所有长度必须先读进局部变量。
- `np.frombuffer(...,'>i8').view(np.uint64)` —— 对大端数组直接 `view` 是按本机序
  重新解释字节，位域解包出来全是垃圾。必须先 `astype(np.int64)` 触发真正的字节翻转。

### 3. 高度定义：跳过植被，不是「最高非空气方块」

PLAN §1.2 写的是取最高非空气方块。照做的话树冠、雪层、草丛会在高度场上打出
+1..+8 的毛刺，中尺度地形结构被噪声盖住。`blockvocab.py` 把方块分成
空气 / 植被覆盖物 / 固体 / 流体四类，扫描时跳过植被，取下面第一个固体或流体。
水**不**跳过，所以水面就是地表（海平面 62），这正是我们想让模型学的。

正确性用 MC 自己的 `Heightmaps.MOTION_BLOCKING` 交叉验证过：逐格吻合，
唯一的差值就来自我们有意剥掉的树冠。

### 4. 数据组织：按 region 存 512×512，patch 在 GPU 上现切

PLAN §1.3 想把相邻 chunk 拼成 patch，需要「按 region 内坐标重排」。
直接按 region 存成 512×512 的二维图就把这个问题消掉了——空间邻接天然保留。

patch 不物化：40k 个 64×64 patch 要 1GB 内存，而且固定切法丢掉了随机偏移。
`encode.py` 只枚举「全有效」窗口的左上角索引，整个数据集（~50MB）常驻显存，
`train.py` 每步直接在 GPU 上按索引切，外加 D4 对称增强。没有 DataLoader、没有主机拷贝。

高度归一化用**分位数**而不是 mean/std：高度分布在海平面 62 处有一根极高的尖峰，
用 std 归一化会把整个陆地压进 [-0.2, 0.2] 的窄带里。

### 5. 离散通道：固定 ±1 one-hot，不用可学习 embedding

PLAN §2 的「简单版」是 embedding 成低维连续向量 + 最近邻解码。实际隐患是
扩散的目标分布跟着 embedding 一起动，训练早期容易塌成一团、解码后所有 token
落到同一类。改用固定的 ±1 one-hot：互相等距、解码就是 argmax，最稳。
代价只是通道数变多（1 + 18 + N_biome），对 64×64 的轻量 U-Net 没有压力。

配套：**损失按组加权**。高度只有 1 个通道，跟几十个离散通道平摊 MSE 的话
几乎不会被优化。三组各占 1/3。

（PLAN 里的 D3PM 离散扩散仍然留给第二版。）

#### one-hot 的代价：U-Net 宽度必须 ≥ 通道数

第一次训练跑到 4000 step，高度通道已经开始出结构，**方块和 biome 仍是纯噪声**。
分组测 eps 预测误差立刻定位到问题：

```
       eps_MSE   高度组   离散组
t=200   0.338    0.0373   0.3468
t=990   0.317    0.0292   0.3212
```

关键是 t=990：此时 ᾱ=1e-8，`x_t ≈ ε`，模型只要把输入原样输出就能拿满分。
高度组做到了（0.029），离散组没有（0.32）。原因是 one-hot 把数据撑到 **69 通道**，
而 U-Net 全分辨率那一层只有 **base=64 宽**——69 维的高频噪声挤不过 64 维通路，
高度只占 1 维所以不受影响。

固定数据只改宽度的 A/B（各 800 step）证实了这一点：

| base | 参数量 | it/s | t=990 cos(pred,ε) | 高度组 MSE | 离散组 MSE |
|---|---|---|---|---|---|
| 64  | 16.5M | 6.4 | 0.737 | 0.0335 | 0.466 |
| 96  | 37.1M | 4.1 | 0.838 | 0.0300 | 0.304 |
| 128 | 65.9M | 2.9 | 0.893 | 0.0250 | 0.207 |

离散组误差随宽度单调腰斩，高度组几乎不动。最终取 **base=128**，
超出 PLAN 估的 10-30M，但 12GB 显存吃得下，质量优先。

> 教训：**用 one-hot 表示离散通道时，U-Net 的最窄一层必须宽于总通道数**，
> 否则高噪声端的恒等映射学不出来，采样必然收敛不到数据流形。
> 换 D3PM 或低维 embedding 可以绕开这个约束，代价见上文。

#### 真正的杀手：数据必须零均值单位方差

改宽之后训练到 4000 step，采样出来仍然是「整片偏高 + 高频毛刺」的糊状物。
定量对照（真实 vs 无条件生成 vs 用真实半张图做条件的续画）：

```
真实         高度 mean= 69.6 std=18.4 中位=62.0  相邻格高差=0.185
无条件生成   高度 mean=101.5 std= 6.8 中位=101.3 相邻格高差=4.446
续画右半张   高度 mean= 97.3 std=25.3 中位= 91.6 相邻格高差=2.689
```

条件和无条件**都坏**，所以不是无条件模式训练不足。而 101.5 恰好是归一化零点。
再拿加噪的真实数据喂模型，它隐含的 x0 预测是 **mean=-0.661 / std=0.304，
与真实的 -0.661 / 0.305 完全吻合**——模型是好的，坏的是采样轨迹：

```
 i    t     ᾱ         x.mean   x0_hat.mean     (真值 -0.937)
 0  999  1.0e-08    -0.000     -0.016
 7  856  4.9e-02     0.002     -0.025
49    0  1.0e+00    -0.073     -0.073   ← 自洽收敛到错误的不动点
```

机制：裸 ±1 one-hot 的全通道均值是 **-0.937**（K 类里只有一个 +1），而扩散先验是
N(0,1)。模型要把轨迹从 0 拉到 -0.937，靠的是 ε 上一个 `√ᾱ·μ` 的偏置；
t→T 时 ᾱ→1e-8，这个偏置量级 1e-4，**bf16 的相对精度 0.4% 表示不了**，
第一步就被舍掉，之后每一步都自洽地停在零均值。

标准 DDPM 不撞这个坑，只是因为它们的数据本来就接近零均值。**我们的不是。**

修法（`Codec`）：每个通道标准化到零均值单位方差。one-hot 通道按类频率
`μ=2p-1, σ=2√(p(1-p))`，并对 σ 设下限使「present」值不超过 4σ——
否则占比 0.5% 的稀有类会给出 14σ 的尖峰。配套把 53 个原始 biome 归成 15 族
（每族 >2%），通道数从 69 降到 34。

修完全通道均值 **-0.937 → +0.003**，1500 step 的采样图就已经有正确的
陆地/水域分块和正确的高度区间。

#### 采样时裁 x0 的范围必须跟着编码走

标准化之后又踩了一次：`ddim` 里 `x0.clamp(-1.5, 1.5)` 是给旧的 ±1 编码写的，
新编码里稀有类的 present 值到 +4σ、高度尾部到 ±5σ，被 1.5 一刀切掉的后果是
**离散通道塌到主类、高度方差只剩真值的 1/5**。改成按 `Codec.bounds()`
逐通道裁（每个 one-hot 通道就两个合法值，高度 ±5σ）：

```
真实                  高度 std=15.57  相邻格高差=0.221
旧 clamp ±1.5         高度 std= 2.97  相邻格高差=1.402   ocean 90.2%
新 per-channel bounds 高度 std=14.55  相邻格高差=3.547   ocean  4.7%
新 bounds + eta=1     高度 std=15.48  相邻格高差=1.599   ocean  2.1%
```

顺带把 `p_uncond` 从 0.25 提到 0.5：条件样本的损失只算未知区，那是个
「照着已知区补全」的低方差回归任务，25% 的份额喂不出无条件生成能力。

#### EMA 需要 warmup

采样用的是 EMA 权重。decay=0.999 的有效窗口是 1000 步，step 2000 时影子权重里
还混着 `0.999^2000 = 13.5%` 的随机初始化权重，采样直接出噪声。
改成 `decay = min(0.999, (1+step)/(10+step))`，前期跟随实际权重。

### 6. 拼接：模型从一开始就按 outpainting 训练

不是训完再想办法拼。U-Net 输入额外拼上 `[已知区域的干净值, 已知掩码]`，
训练时随机生成边带/矩形掩码（25% 概率给全零掩码，保留无条件生成能力）。
损失只在未知区域上算——已知区域的噪声由 `x_t` 和真值直接反解得到，是白送的题。

所以同一个 checkpoint 既能无条件采样，也能按邻块边缘续画，还能做残缺补全。
采样时每一步把已知区域用真值加噪硬贴回去，杜绝漂移；重叠区再做线性 blend。

### 7. 参数化：v-prediction，不是 ε-prediction ← **决定成败的一处**

前面几处修完，训练到 9000 step 仍然不对：地形整片饱和、高频毛刺。量化下来是
**低频/DC 分量发散**：

```
                   patch内 std   patch间(DC) std   相邻格高差
真实                   4.29          13.97           0.271
ε-pred eta=0 50步     10.20          31.95           3.275
ε-pred eta=1 50步      5.80          32.28           1.430
ε-pred eta=1 250步     6.20          33.84           1.391   ← 加步数完全没用
```

把采样步数从 50 加到 250 毫无改善 → 不是离散化误差。而模型在**真实加噪数据**上
t=600 时的 block/biome 重建正确率是 99.8%/99.9% → 也不是容量不足。

问题出在 ε 参数化本身：cosine schedule 下 ᾱ_T ≈ 1e-8，而样本的 DC 分量恰恰是在
t→T 这一端定下来的。ε 参数化下
```
x0 = (x_t − √(1−ᾱ)·ε̂) / √ᾱ        1/√ᾱ = 1e4
```
ε̂ 的任何误差都被放大一万倍，DC 完全失控。**v-prediction** 下
```
v  = √ᾱ·ε − √(1−ᾱ)·x0
x0 = √ᾱ·x_t − √(1−ᾱ)·v̂         t=T (ᾱ=0) 时退化成 x0 = −v̂
```
模型在最高噪声端直接输出信号本身，没有任何放大。

换成 v-pred 后同样 30k step 的结果：

```
                 相邻格高差   block 分布              biome ocean
真实                0.244     grass 46% / water 42%      31%
v-pred DDIM-400     0.318     grass 47% / water 49%      41%
```

高频粗糙度从 3.3 降到 0.318（真值 0.244），方块/biome 比例基本对上。

## 结果（30k step，37.0M 参数，99.5 分钟）

`outputs/eval.png` 六张图：

| 指标 | 结论 |
|---|---|
| 高度直方图 | 海平面 62 的尖峰位置和形状都对；山地尾部（80-130）偏少 |
| 径向功率谱 | 生成与真实在所有波数上平行，粗糙度标度正确 |
| 半方差函数 | 形状一致，幅度偏低（lag8 比值 0.73） |
| biome 占比 | 前 4 类（ocean/forest/snowy/plains）对得上；中频类（savanna/river/taiga/desert）几乎不生成 |
| 表层方块频率 | grass 0.47 vs 0.48、water 0.49 vs 0.40，block KL = 0.223 |
| **每种方块的平均高度** | **几乎完全重合**：水 62、雪块 118、石头 83/70——模型自己学到了「水在低处、雪在高处」 |

`outputs/stitched.png`（8×8 tile = 400×400 方块）：高度场跨 tile 完全连续，
接缝比值 0.91（缝上高差 0.332，全图平均 0.363，≈1 即无可见接缝）。

### 已知不足（诚实版）

1. **大尺度高度变化偏保守**：patch 间高度均值的 std 是 10.5，真值 19.2。
   加采样步数能补回一半（50 步 6.8 → 400 步 10.1 → 1000 步 10.5 后饱和），
   剩下的是训练量。生成的地形都是「中等起伏」，深海沟和高山比真实少。
2. **中频 biome 缺失**：只稳定生成占比最高的 4 个族。稀有类在 one-hot 标准化时
   被限幅压低了信噪比，30k step 不够把它们学出来。
3. **拼接时离散通道会塌**：栅格顺序逐块条件生成，误差朝主导类累积。
   高度场没这个问题（seed 3 的 std 16.2，与真值 15.7 吻合），但方块/biome 会
   收敛到单一类；换种子有的会整张塌成海洋。无条件单块采样不存在这个问题。

### 下一步（按收益排序）

- 训练量翻倍到 100k step——上面三条都主要受训练量限制
- biome/方块换 D3PM 离散扩散（PLAN §2 的进阶版），绕开 one-hot 的限幅问题
- 拼接改成粗到细：先在低分辨率上生成整张大图的骨架，再逐块细化，
  避免序贯条件的误差累积
- 加条件维度（PLAN §8/§9 的核心诉求）。当前的 outpainting 训练已经附带给了
  「残缺补全 / 按草图续画」这一个可控维度
